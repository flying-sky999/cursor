PersonaRepair

面向长视频人物编辑的细粒度音画诊断与保真定点修复系统

长视频 多人物 音视频编辑 Agent 错误定位 最小范围修复
一句话 通用 Agent 负责“完成编辑”，PersonaRepair 负责“发现哪个人物的哪一秒为什么错了，并且只重做必要部分”。

系统面向三个已有执行模型：人物画面与台词联合替换、画外音修改、纯视觉修改。本文不把“调用三个模型”当作创新，而把重点放在最终成片的诊断、工具副作用预测和低破坏修复。

1. 要解决的问题

长视频编辑的难点不是单个模型不会生成，而是不同模型完成局部任务后，人物、声纹、台词、嘴型和背景之间很容易失去一致性。

例如用户提出：

把 12:10–13:00 的张三替换成李四；
把他说的“明天见”改成“周末见”；
18:03 的画外音语气改得严肃一点；
其他人物、环境声和背景不要变化。

系统需要自动判断：

  • 张三在哪些镜头出现，哪些镜头中正在说话；
  • 人物说话时嘴部是否可见，是否需要重新生成口型；
  • 18:03 是画外音，因此只能修改音频，不能动视频；
  • 哪些内容已经正确，修复过程中必须锁定；
  • 如果编辑失败，应重新运行哪个工具、处理哪一秒和哪个区域。

2. 为什么不是普通的 AVE-Agent

AVE-Compass 是一个音视频编辑 Benchmark，但论文同时提出了 AVE-Agent 方法。它已经能把复杂指令拆成有依赖关系的视觉、音频和语音子任务，并依据 evaluator feedback 重试。因此，“任务分解＋工具路由＋反思”不能作为我们的核心创新。

维度AVE-AgentPersonaRepair
核心目标完成通用音视频编辑诊断并修复最终成片
反馈粒度子任务或整体评价人物、关系、时间、模态
错误输出某个分支需要改进哪个人物、哪一秒、什么错误
修复方式重试、重混、重生成预测副作用后求最小动作
重点场景一般音视频编辑长视频、多人物、画外音
已被占用的主张：首个音视频编辑 Agent、首个语义依赖图、首个 Edit Closure、首个局部重执行、首个人物外观/声纹/台词联合编辑。这些方向分别已有 AVE-Agent、AVA-Encoder、Crayotter、InstructAV2AV 和 AVI-Edit 等工作。

仍然存在的缺口

现有公开工作中，没有发现单篇方法同时完成：

  • 长视频跨镜头人物、人脸、声纹和台词的持续绑定；
  • 对最终渲染结果进行人物中心、时间段级错误定位；
  • 把错误关联到具体工具调用；
  • 预测候选修复对已正确内容的副作用；
  • 求解最小重做时间、空间和模态，并验证修复没有引入回退。

4. 三个核心模块

4.1 人物音画状态建模

先使用镜头检测、人物跟踪、ASR、说话人分离、声纹识别和 Active Speaker Detection 建立长视频索引。共享 Audio-Video MLLM 的 State Adapter 将用户指令绑定到实际实体和时间：

人物 P03
├── 人脸轨迹：F07、F12、F18
├── 声纹：W03
├── 台词：U17、U18、U24
├── 画内说话：12:24–12:27
├── 画外说话：12:27–12:29
└── 保护项：背景、人物 P04、环境声

这个结构是系统状态，不主张它本身是全新知识图。所有目标必须绑定到真实 ID 和时间戳；无法确定时询问用户，而不是让大模型猜测。

4.2 细粒度音画错误定位

Diagnosis Adapter 比较原视频、编辑视频、用户要求和工具轨迹，输出四个字段：

{
  "person": "P03",
  "time": "12:26.2–12:27.1",
  "error": "嘴型比新台词慢 240 ms",
  "responsible_action": "lip_edit_05"
}

诊断由专业证据和 MLLM 共同完成：ASR 检查台词，speaker verification 检查声纹，Active Speaker 与 SyncNet 类模型检查说话者和口型，人脸/人体特征检查跨镜头身份，源—结果差异检查背景及环境声是否被误改。

4.3 工具效果预测

Effect Model 不是 VLM，而是小型 Transformer 或 MLP。它学习每个工具在不同视频条件下的真实能力边界：

候选动作：只重做 12:26.2–12:27.1 的嘴部
修复 lip-sync 的概率：0.92
破坏人物身份的概率：0.03
破坏背景的概率：0.01
预计修改时长：0.9 秒
预计调用成本：0.4

训练数据来自三个编辑模型的实际执行日志，包括成功、失败和人工修正记录。这样，Agent 不再只根据工具说明或 GPT 常识猜测工具效果。

5. 训练什么

不是训练三个新的 VLM。推荐配置是一个共享 AV-MLLM、两个 LoRA Adapter、一个轻量 Effect Model，加上不需要训练的优化算法。

模块模型类型训练方式
State Adapter共享 AV-MLLM 的 LoRA结构化状态与时间监督 SFT
Diagnosis Adapter共享 AV-MLLM 的 LoRA真实失败＋可控故障 SFT
Effect Model小 Transformer/MLP工具执行前后约束差分监督
约束优化器ILP/A* 等算法不训练
三个编辑模型已有执行器主实验先冻结

训练数据

  1. 记录人工编辑时的目标人物、时间、工具、参数、结果和修正方式；
  2. 让三个执行器在不同人物、镜头、遮挡和声音条件下运行；
  3. 保存失败结果，而不是只保留成功样本；
  4. 自动注入口型偏移、声纹交换、错误说话者、身份漂移和非目标污染；
  5. 用人工子集校准所有自动判断指标。
强化学习暂不放进主方法。 如果后续实验表明工具顺序、检查时机和失败重试构成明显的长期决策问题，可以在补充实验中加入离线 Agentic RL。当前先用诊断＋Effect Model＋约束优化保持方法简洁，并证明每个组件的必要性。

6. 最小范围修复算法

对于每个失败，系统生成若干候选修复动作。每个动作都有修复概率、风险、修改时长、空间范围和成本。优化器选择总成本最低且能够覆盖全部失败的动作组合。

最小化：工具成本 + 修改时长 + 修改区域 + 破坏正确内容的风险

同时满足：

  • 所有检测到的错误都有高概率被修复；
  • 原本通过的人物、声纹、台词、背景和环境声约束不能明显退化；
  • 工具之间的前置条件和调用顺序合法；
  • 互相冲突的工具动作不能同时执行。
输入：失败列表、错误时间、工具效果预测
1. 生成候选修复动作
2. 删除成本更高且效果更差的候选
3. 求解最低成本合法动作集合
4. 仅在副本上执行选中动作
5. 检查失败是否修好
6. 检查原本正确的内容是否退化
7. 通过则提交；失败则回滚并换候选

No-Regression

“修复成功”不能只看目标错误是否消失，还要检查修复是否造成新错误。建议报告：

NRR = 修复后仍然正确的原通过约束数 ÷ 修复前通过约束总数

需要明确：这是相对于已枚举约束和验证器的无回退，不是对所有人类感知属性的绝对保证。

7. 如何证明方法有效

必须比较的 Baseline

  • 不修复、整段重新生成、固定时间窗口局部重做；
  • GPT/Video-MLLM ReAct；
  • AVE-Agent 式 evaluator feedback 重试；
  • 独立 ASR、声纹、ASD、Sync 指标组合；
  • 没有 Effect Model 的规则规划；
  • 人工/Oracle 错误时间＋相同编辑后端。

主要指标

能力指标
错误判断约束 F1、AUROC、概率校准误差
时间定位Temporal IoU、区间 mAP、边界误差
人物与声音人脸/声纹一致性、speaker attribution
台词与同步WER/CER、lip-sync offset
修复效果单轮成功率、预算内成功率、NRR
低破坏重做时长、像素/音频修改比例
效率工具调用次数、GPU 时间、API 成本

新 Benchmark 应覆盖

  • 2–20 分钟主测试视频，30–90 分钟压力测试；
  • 多人交替、同时说话、背脸、遮挡、镜头切换；
  • 同一人物跨镜头重新出现及外观变化；
  • 画内说话切换到画外音；
  • 人物＋台词联合替换、只改台词、只改人物、只改画外音、纯视觉修改；
  • 每个错误的精确时间、人物、错误类型和允许修复范围。
最重要的实验不是“最终视频更好看”。 必须证明相对 AVE-Agent：定位更准确、重新生成范围更小、原本正确内容退化更少，而且优势在长视频、多人物和画外音条件下扩大。

8. 创新性判断

贡献 A

成片诊断

不是评价任务计划，而是从最终像素和声音中定位人物关系错误及时间证据。

贡献 B

效果感知修复

显式学习生成工具可能修好什么、又可能破坏什么，再进行约束优化。

贡献 C

新评测任务

首次系统评测长视频多人物音画编辑中的错误定位、修复范围和无回退。

能否撑起 CVPR 方法论文：可以形成完整研究命题，但不能预先声称足够 Oral。决定性因素是 Benchmark 的质量、相对最邻近工作的结果幅度，以及三项贡献是否都能通过消融被单独证明。

最大风险有两个：第一，诊断器只是把已有 ASR、声纹、口型和人脸模型做 ensemble；第二，优化器只是普通 ILP 的应用。必须证明跨模态关系推理产生额外收益，并证明学习到的工具副作用显著优于固定规则和整体重试。

9. 建议实施顺序

  1. 先建立执行接口。 统一三个编辑模型的输入、输出、时间范围、掩码和日志格式。
  2. 收集失败。 在真实编辑过程中保存失败结果和人工修正，不急着训练 Agent。
  3. 完成状态索引。 跑通人物跟踪、ASR、声纹、active/off-screen speaker。
  4. 训练诊断器。 先做台词、声纹、口型、人物身份和非目标保持五类错误。
  5. 训练 Effect Model。 学习三个工具的成功率和副作用。
  6. 实现约束修复。 先用 ILP/搜索，不加入 RL。
  7. 建立 Benchmark。 给出可复现的错误时间和最小合法修复范围。
  8. 最后评估是否需要 RL。 只有多步顺序确实是主要瓶颈时再加入。

10. 关键依据

  1. AVE-Compass / AVE-Agent：音视频编辑 Benchmark、任务拓扑、工具路由和 evaluator feedback。
  2. AVA-Encoder：Film Knowledge Graph、跨镜头状态和关联子图编辑。
  3. InstructAV2AV：人物外观、声纹和台词的可组合联合编辑。
  4. AVI-Edit，CVPR 2026：实例级音画同步编辑与非目标保持。
  5. CineSRD，CVPR 2026：长视频人物、声纹、台词和画外说话人识别。
  6. Crayotter：长视频可追踪工具流程与选择性重执行。
  7. RefineCut：显式约束、局部补丁和 no-regression。
  8. NeuS-E：时序失败定位与局部视频重生成。
  9. MTAVG-Bench，ACL 2026：多说话人音视频生成故障分类。
